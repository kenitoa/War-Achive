# 기록 사전의 근거 정책

## 문제와 변경 범위

기존 두 장소 항목은 `NAS/back/scripts/curate-initial.ts`에서 Wikidata 설명과 P625 대표 좌표를 가져온 연결 메타데이터였다. 발행본에서 두 항목의 `warIds`는 비어 있고, 직접 참조하는 자료도 없었다. 이 값은 검증된 역사 사전이나 촬영 위치의 증거가 아니다.

새 사전은 `lib/dictionary.ts`의 별도 편집 계층으로 구성한다. 기존 Wikidata ID 경로는 보존하고, 새 3개 경로를 추가한다. `content/archive.json`, NAS 카탈로그, 자동 발행 계약을 수정하지 않는다.

## 등재와 표시

- 확인 내용은 문장별로 근거 문헌 ID와 구체적인 절·항·본문 위치를 요구한다.
- 기관 역사 해설, 소장처 해제, 원문 전사를 구분한다. 기관이 올린 글이라고 자동으로 1차 사료가 되지 않는다.
- 출처 URL은 이번에 확인한 기관의 HTTPS 호스트로 제한한다. 이는 입력 실수 방지 장치이며 진실성을 판정하는 알고리즘이 아니다.
- 기본 목록은 내용별 근거가 등록된 항목만 표시한다. 가져온 항목에 공식기관 URL이나 정밀 좌표가 있어도 자동 승격하지 않는다.
- ‘근거 문헌 연결’은 문헌 대조와 연결을 뜻한다. 전문 연구자의 심사·동료평가·전체 사실 보증을 뜻하지 않으며 상세에서 전문가 검토 미실시를 표시한다.
- 출처 수는 문헌 수다. 같은 기관의 문헌 여러 건을 독립된 여러 검증기관처럼 표현하지 않는다.
- 직접 원자료 연결은 발행본의 `record.entityIds`에 명시된 관계만 사용한다. 같은 `warIds`, 검색어, 유사 지명으로 직접 증거 관계를 만들지 않는다.
- 기존 설명과 좌표는 접힌 ‘가져온 원래 설명·좌표’에 보존하며, 역사적 전투·피해·촬영 위치로 쓰지 않는다.
- 원 발행본에 관련 전쟁이 없으면 해당 전쟁에 대한 편집 항목도 등재하지 않는다. 공개본이 없는 초기 상태에서도 빈 사전을 안전하게 표시한다.

## 검증과 후속 업무

`npm.cmd run test`에 근거 누락·출처 위장·자동 승격·임의 자료 연결 방지 검사를 포함한다. 정적 빌드 후 `node scripts/dictionary-smoke.mjs`와 기존 브라우저 회귀 검사를 실행한다. 정정 요청은 사전 ID·경로를 기존 접수 메시지에 전달하며 새 API 필드를 추가하지 않는다.

배포 전 전문 연구자 검토와 장기 링크 보존 정책 수립이 남아 있다. 새 DB 마이그레이션·환경 변수는 없다. 편집 계층·사전 화면·정정 요청 문맥 표시를 이전 버전으로 복구하면 롤백 가능하다. 운영 NAS나 배포 사이트에 이 변경을 적용했다는 증거와는 별개다.
