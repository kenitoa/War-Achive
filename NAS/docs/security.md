# 보안과 공개 정책

- 관리자 토큰은 로그인 교환에만 사용한다. 세션은 HttpOnly 쿠키이고 브라우저 저장소에 토큰을 넣지 않는다. 변경 요청은 CSRF 토큰과 정확한 origin을 확인한다.
- 관리자 세션은 API 재시작 시 폐기된다. 회원 세션은 DB에 해시로 저장하고 만료·로그아웃·비밀번호 변경 시 무효화한다.
- 운영자, 편집자, 검수자, 발행자 권한을 서버에서 다시 검사한다. 별도 검수 인력이 없으면 자체 검수임을 운영 정책에 기록한다.
- 회원 비밀번호는 개별 난수 salt와 scrypt로 저장한다. 이메일 인증·이메일 발송은 설정 없이 수행했다고 표현하지 않는다. 복구는 관리자가 발급한 단기 일회성 토큰으로 수행하며 기존 세션을 폐기한다.
- 입력은 Zod로 런타임 검사하고 SQL은 파라미터를 바인딩한다. 내부 DB 오류와 스택은 클라이언트에 반환하지 않는다.
- 수집기는 허용된 제공자 호스트만 요청하고 외부 입력으로 내부 IP·임의 URL을 가져오지 않는다. 제한된 응답 크기·시간·리디렉션 정책을 적용한다.
- 원자료의 텍스트는 지시문이 아닌 비신뢰 데이터다. 실행 코드로 평가하거나 HTML로 직접 삽입하지 않는다.
- 공개 자료는 공용 스키마로 필드를 선별한다. 원본 JSON, 운영 메모, 작업 오류, 연락처, 비밀키, 인증 DB를 공개하지 않는다.
- 공개 메타데이터는 원 소장처 설명이며 역사적 사실 전체가 독립 검증되었다는 뜻이 아니다. 날짜·위치·권리·판독·번역의 불확실성을 별도 표시한다.
- 개인정보/민감 자료/권리 불명은 검토 대상으로 둔다. 파일 해시는 무결성 검사이며 역사적 진위 인증이 아니다.
- 공개본 철회 시 현재 사이트뿐 아니라 이미지, 검색 색인, CDN, 이전 배포 URL을 확인한다. 원본의 보존·삭제 여부는 별도 정책으로 결정한다.

## 외부 공개

Compose는 관리자 포트를 NAS loopback에 바인딩한다. VPN/SSH 터널로 관리하고 DB 포트는 외부에 공개하지 않는다. 공개 계정 API가 필요하면 경로 허용 목록을 적용한 별도 HTTPS 게이트웨이를 둔다. 공개 앱은 NAS DB에 직접 연결하지 않는다.

## 백업

관리자 화면의 메타데이터 JSON은 전체 DB 백업이 아니다. 전체 DB·원본·설정 복구에는 운영 백업 스크립트를 사용한다. 계정 정보가 있는 백업은 암호화하고 최소 권한으로 별도 장소에 보관한다. 비밀값은 Git/공개 산출물에 넣지 않는다.
