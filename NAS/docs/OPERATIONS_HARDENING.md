# 2026-10-19 운영 보완 계획

## 목적과 범위

회원가입·자료 접수를 각각 시간당 100회로 조정하고, NAS 인증 만료로 인한 중단을 예방한다. Tailscale 내부 관리자 접속과 War Archive 서비스 전체 복원을 실제 환경에서 검증하며, NAS 밖의 암호화 백업을 구성한다. DSM 운영체제와 다른 프로젝트 전체 복원은 War Archive 백업 범위와 구분한다.

## 구성요소와 데이터 흐름

- 공개 사이트 → 기존 Vercel API 경로 → 공개 gateway → API의 가입/접수 한도. 로그인·비밀번호 재설정 제한과 신뢰하지 않는 프록시 헤더 정책을 유지한다.
- 관리자 PC → Tailscale 전용 HTTPS 포트 → loopback API의 관리자 화면. 공개 Funnel 포트와 분리한다. 현재 다른 서비스의 Serve 설정은 새로 읽은 ETag로 보존한다.
- PostgreSQL dump + 원본/제작 파일 + 발행 파일 + 비공개 운영 설정/복구 코드 → 암호화 → 사용자가 지정한 NAS 외부 저장소. 복호화 키는 백업 파일과 별도로 보관한다.
- 백업 → 새로운 전용 Docker 프로젝트/볼륨/내부 네트워크 → 복원 DB/API/파일 해시 검증. 운영 worker와 공개 발행을 복원 환경에서 실행하지 않는다.

## 순서

1. 현재 NAS·Tailscale·배포·백업을 읽기 전용으로 조사한다.
2. 한도 변경 및 100번째/101번째 요청 경계 테스트를 작성한다.
3. Tailscale 공식 서버 인증 유지 방식과 실제 관리자 권한을 확인하고, 적용 가능한 설정을 준비한다.
4. 기존 설정을 보존하는 사설 관리자 경로를 준비하고 인증·CSRF·공개 차단을 검증한다.
5. 격리된 Docker 환경에 실제 백업을 복원하고 DB/파일/화면/세션 폐기를 검사한다.
6. 지정된 외부 저장소로 암호화 백업을 전송하고 내려받은 사본의 복구 가능성을 검사한다.
7. lint·타입 검사·테스트·빌드 후 배포하고 실제 배포 버전과 동작을 확인한다.

## 위험과 방지

인증 만료 정책 변경은 장치의 접근 지속 시간을 바꾼다. 관리자 화면은 Tailscale 내부에서만 제공하고 HTTP 인증·권한 검증을 유지한다. 복원은 새 대상만 허용하고 기존 운영 DB/볼륨을 덮어쓰지 않는다. 비밀 설정과 개인 키는 암호화된 백업에만 포함하고 로그·Git에는 기록하지 않는다. 외부 저장 위치는 사용자 지정 후 연결한다. PC 백업은 해당 PC가 켜져 있을 때 실행되며, 지리적으로 분리된 외부 보관과는 구분한다.

## 검증과 롤백

한도 API 경계·위조 프록시 헤더·인증 회귀 테스트를 실행한다. 사설 관리자 HTTPS와 로그인/로그아웃/CSRF 및 공개 gateway의 관리자 차단을 검사한다. 복원 환경에서 DB 통계, 원본·제작 파일·발행 스냅샷 SHA-256과 API 건강 상태를 검증한다. 암호화 파일의 변조·잘못된 키·중복 출력 거부를 테스트한다.

애플리케이션은 이전 정상 커밋으로 되돌릴 수 있다. 추가한 사설 Serve 서버만 조건부 제거하고 다른 서비스는 보존한다. 장치 인증 만료 정책은 원래 상태로 복구할 수 있다. 새 백업 작업은 비활성화할 수 있으며 기존 백업·운영 자료는 자동 삭제하지 않는다. DB 스키마 변경은 예정되어 있지 않다.
