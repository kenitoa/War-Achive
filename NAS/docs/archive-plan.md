# 전쟁 아카이브 기획과 구현 범위

## 목적

전쟁을 미화하거나 단일 관점의 설명으로 정리하는 대신, 다양한 기록을 원 출처·시기·장소·관계·이용 조건과 함께 보존하고 탐색하게 한다. 사진·문서·영상·음성·지도·증언·연구·수치 등 유형을 수용하는 구조를 만들되 실제 수집 범위와 비어 있는 영역을 명시한다. 전체 전쟁 자료를 이미 확보했다는 표현을 사용하지 않는다.

이용자는 전쟁에서 자료로, 자료에서 사건·인물·조직·장소·장비로 이동한다. 연구·교육용 재탐색을 위해 URL 검색 조건, 정확한 출처 링크와 페이지/시간 인용, 개인 메모·모음·비교·내보내기를 제공한다. 서로 다른 주장과 수치는 하나의 확정값으로 합치지 않고 출처·범위·방법·불확실성을 별도 기록한다.

## 정보 구조

| 영역 | 내용 |

| 전쟁 탐색 | 개요·기간·지역·연관 자료·출처·아직 확인하지 못한 범위 |
| 자료실 | 키워드·전쟁·유형·언어·기간·권리·판독 상태·정렬·페이지와 URL 공유 |
| 자료 상세 | 원 소장처 식별자·설명·날짜 정밀도·권리·귀속·민감도·검수 상태·인용·변경 이력 |
| 지도·연표 | 출처에 명시된 좌표와 날짜만 표시. 가까운 지도 표식은 묶어 선택하고 좌표를 임의로 이동하지 않음 |
| 기록 사전 | 사건·인물·조직·장소·장비의 연결된 기록. 실자료가 없는 분류는 빈 상태 |

| 내 서재 | 브라우저 저장·메모·모음·비교·JSON 백업·병합·손상 복구. 선택적 회원 동기화 |
| 소개·정책 | 수집 범위·권리·개인정보·불확실성·정정·자료 기증/제안 절차 |

## NAS의 세 가지 핵심 원칙

### 지속 수집

출처를 provider·질의·전쟁·범위·주기·공개 정책으로 등록한다. 초기 과거 자료 수집, 새 자료 확인, 기존 식별자의 순환 재확인을 구분한다. 진행 페이지·페이지 크기·재확인 offset을 DB에 보존한다. API 차단·호출 제한·원문 삭제는 출처 상태와 실패 기록으로 남기고 다른 출처 작업을 계속한다. 허용된 제공자 URL만 요청하며 임의 웹사이트 전체 크롤링으로 범위를 확장하지 않는다.

### 지속 정제와 게시 자료 제작

원 응답/업로드 파일은 SHA-256과 불변 경로로 보존한다. 원본과 정규화 데이터, 편집본과 변경 후보, 텍스트 추출과 번역, 메타데이터와 역사적 사실 검증을 구분한다. 자료 중복은 안정 식별자와 해시로 처리하며 수정 이력은 버전으로 남긴다. 날짜 미상·추정 위치·수치 이견·권리 불명은 명시적인 상태다.

공개 가능한 설명·인용·출처 정보와 파일별 제작물을 작업 큐로 만든다. 실제 도구가 있을 때 PDF 추출·OCR·영상 정보/프레임·이미지 축소를 실행한다. 도구나 공급자가 없으면 사용 불가 상태로 남긴다. 자동 번역·AI 해설·음성 전사는 실제 제공자와 검수 체계 없이 만들어졌다고 표시하지 않는다. 외부 원문의 지시문을 실행하거나 운영 설정으로 취급하지 않는다.

### 지속 자동 업로드

출처 정책상 허용된 낮은 위험 메타데이터는 자동 공개 대상이 된다. 민감도·개인정보·권리 불명·내용 변경 후보는 검수 대기다. 사람의 내용 검수와 원 소장처 확인을 구분한다. 미디어 공개는 자료의 검수와 파일별 권리를 추가로 확인한다.

공개 스키마로 필드를 선별한 불변 snapshot과 manifest를 만들고, GitHub의 지정 파일만 갱신한다. 공개 웹은 이 snapshot으로 재빌드한다. 전송 성공·원격 재조회·실제 배포의 릴리스 ID/해시 확인을 구분한다. 재시도는 같은 공개본을 사용하고 철회는 이전 공개본의 재전송보다 우선한다.

## 관리자와 운영

운영 현황·출처·자료 검수·사전/주장·제작 파일·작업 큐·발행·정정/제보·감사·설정/백업·회원 복구를 비공개 관리자에서 처리한다. admin/editor/reviewer/publisher 권한을 서버에서 확인한다. 변경 요청에는 CSRF, 자료에는 revision 충돌 검사를 적용한다. OTP는 설정 시 사용한다.

장애는 큐 지연·재시도·출처 오류·발행 대기·worker heartbeat로 관찰한다. 원본·DB·릴리스 백업과 암호화, 새 환경 복원, Windows 로컬 데이터의 NAS 이전 절차를 제공한다. 운영 DB는 NAS PostgreSQL이고 공개 Vercel은 정적 자료만 보유한다. NAS가 꺼져도 이미 배포한 공개본은 열람할 수 있다.

## 공개·철회 정책

권리는 표시·다운로드·재사용·파생 제작을 구분한다. 권리 표시는 소장처 설명을 근거로 기록하고 출처를 연결한다. 민감 썸네일은 자동 노출하지 않는다. 철회는 현재 공개본·검색·미디어·CDN에 반영하고 원본 보존 여부는 별도 판단한다. GitHub 이력·이전 배포 URL·제3자 사본은 운영자가 별도 조사한다.

## 초기 실제 범위와 확장

초기 공개본은 Wikimedia Commons의 한국전쟁·제1차 세계대전·제2차 세계대전 질의에서 수집한 118건이며, 검토 대기 자료는 별도로 보존한다. 세 전쟁과 출처별 모음, 출처에 명시된 일부 좌표, 실제 Wikidata 장소 참조를 연결한다. 현대 기념관/기념물 사진도 포함되므로 사진 생산 시점과 전쟁 발생 시점을 혼동하지 않도록 설명한다. LOC 연결 모듈은 있으나 현재 접근 차단으로 활성 수집 근거로 사용하지 않는다.

새 제공자는 기존 연결 모듈의 URL 제한·응답 검증·정책·원본 보존·checkpoint 계약을 따른다. 범위는 검수 인력과 제공자 이용 조건에 맞춰 확장한다. 결제·유료 이용·불필요한 소셜 기능은 이 아카이브 요구 범위에 추가하지 않는다.
