# 전쟁 아카이브 구현 계획

## 목적과 범위

사용자가 승인한 전체 서비스 기획과 다음 NAS 최상위 원칙을 실제 동작으로 연결한다.

1. 지속적인 전쟁 관련 데이터 수집
2. 지속적인 데이터 정제와 게시 가능한 자료 제작
3. 지속적인 자동 업로드와 발행 결과 검증

최상위 작업 폴더는 NAS와 Vercel만 유지한다. 기존 NAS/.env 및 NAS/back/.env의 비밀값을 보존한다. 사용자 확인에 따라 NAS/.env의 비밀이 아닌 발행 대상은 kenitoa/War-Achive와 새 공개 사이트의 release.json으로 갱신한다. 원본, 운영 DB, 인증 정보는 공개 산출물에서 제외한다.

## 구성과 데이터 흐름

- NAS/back: TypeScript API, 도메인/응용/인프라 계층, 영속 작업 큐, 마이그레이션, 수집 연결 모듈, 정제/공개 정책, 발행, 보존.
- NAS/admin: 비공개 React 관리자. 출처, 검토, 작업, 발행, 감사, 운영 요청을 실제 API로 관리한다.
- Vercel: Next.js 공개 사이트. 버전이 고정된 공개 스냅샷으로 검색/전쟁/자료/관계/지도·연표/주제 모음/서재를 제공한다.
- 운영 DB는 PostgreSQL, 로컬 통합 검증은 파일에 영속 저장되는 PGlite를 사용한다. 로컬 검증을 실제 NAS PostgreSQL 검증으로 표현하지 않는다.
- 출처 발견 → 원본 보존 → 정제 작업 → 공개 판정 → 공개본 생성 → 미디어/콘텐츠 전송 → 실제 반영 확인. 새 출처는 출처별 공개 정책을 확인한다.
- 공개 스키마는 NAS 도메인에서 관리하고 웹/관리자에 생성 복사한다. 원본·비공개 메모·개인정보를 필드 허용 목록으로 제외한다.

## 구현 순서

1. 공용 공개 계약, DB와 추가형 마이그레이션, 출처 정책, 영속 큐.
2. 실제 출처 연결, 중복·버전·진행 위치, 정제·자료 제작·발행.
3. API 입력 검증, 관리자 역할·세션·CSRF·감사, 계정과 개인 서재.
4. 관리자와 공개 사이트. 목 데이터를 운영 화면에 넣지 않는다.
5. 자동 운전, Docker 실행, 백업/복구, 발행/철회/실패 처리 문서.
6. 실제 자료 입수, 공개본 생성, 앱 전체 검사와 브라우저 점검.

## 주요 위험과 대응

- 외부 API 차단/호출 제한: 출처별 상태와 재시도, 진행 위치 보존, 다른 출처의 작업 계속.
- 저작권·개인정보·진위: 메타데이터 중심 공개, 개별 권리·검수 상태, 불확실성 보존, 예외만 검토 대기.
- 재시작·중복·임대 만료: DB 큐, 멱등 키, 단계별 영속 기록, 제한 재시도.
- 비공개 유출: 공개 스키마 허용 목록, 안전한 HTTP URL, 인증/권한/CSRF, 공개본 유출 회귀 검사.
- 잘못된 발행: 불변 발행 ID, 파일 해시, 전송 뒤 결과 검증, 기존 공개본 유지.
- 철회 자료의 재노출: 철회 상태를 롤백보다 우선하고 이전 배포까지 운영 절차로 확인.

## 검증

각 애플리케이션에서 npm run lint, npm run typecheck, npm run test, npm run build를 실행한다. 영속 저장, 재시작, 큐 임대/재시도, 중복, 비공개 제외, 철회, 권한 우회, CSRF, 서재 충돌/손상 복구를 검사한다. 실제 외부 수집·실제 원격 배포·NAS/Docker·물리 기기 검증 범위는 각각 구분한다.

## 롤백 및 복구

기존 환경 파일과 원본을 덮어쓰지 않는다. DB 변경은 마이그레이션으로 수행하고 데이터 삭제 대신 이전 코드/공개본으로 복구한다. 코드 복사와 운영 데이터 볼륨은 분리한다. 복구 전 현재 DB와 파일을 별도 백업하며 철회 제한을 다시 적용한다. 토큰·원본·데이터는 Git에 넣지 않는다.
