# 2026-07-13 작업 기록

## 오늘 목표

전쟁 역사 아카이브를 다음 운영 구조로 정리했다.

```text
NAS Docker
  → 30분마다 등록된 역사 주제와 출처 전체를 최대한 수집
  → 관련 등록 출처 전체 수집 및 중복 제거
  → 신뢰도·연관성·맥락 라벨링
  → 10분 가공 구간에서 역사 큐레이터 양식으로 정보화
  → 40분마다 가공 완료 공개 기록 1건을 GitHub에 누적
  → GitHub Pages 자동 배포
```

백엔드는 공개 API 도메인을 사용하지 않고 NAS에서 수집·가공을 담당한다. 프런트엔드는 NAS에 직접 접속하지 않으며 GitHub 저장소에 누적된 정적 기록만 사용한다.

## Front 작업

- `front`를 독립 Git 저장소로 구성했다.
- 원격 저장소를 `https://github.com/kenitoa/warsachive.git`로 연결했다.
- 기본 브랜치 `main`과 원격 `origin/main` 연결을 확인했다.
- GitHub Pages를 GitHub Actions 방식으로 활성화했다.
- Actions 변수 `SITE_URL=https://kenitoa.github.io/warsachive`를 등록했다.
- Next.js 공개 아카이브, React 관리자 화면, React Native 모바일 구조를 게시했다.
- 공개 기록은 `front/web/content/archive.json`에서 정적으로 읽도록 구성했다.
- 상세 기록 페이지, sitemap, robots.txt, manifest와 구조화 데이터를 생성하도록 구성했다.
- GitHub Pages 공개 주소의 HTTPS 200 응답을 확인했다.

## Back 파이프라인 작업

- 처리 순서를 `수집 → 라벨링 → 정보화`로 고정했다.
- `topics.json`에 등록된 모든 역사 주제와 출처를 30분 수집 작업마다 모두 시도하도록 구성했다.
- 하나의 수집 사이클에서 가능한 한 많은 역사 사료와 자료를 수집하고, 중복 자료는 저장 단계에서 제거하도록 구성했다.
- 문서 ID, 원문 URL, 본문 SHA-256 해시로 중복을 방지한다.
- 같은 주제의 여러 문서를 하나의 정보화 기록으로 통합한다.
- 수집 완료 주제와 마지막 성공 시각을 NAS 볼륨에 저장한다.
- 기본 수집 간격을 30분으로 설정했다.
- 기본 발행 간격을 40분으로 설정했다.
- 수집 후 발행 전 10분을 데이터 가공 구간으로 설정했다.
- GitHub Contents API로 `kenitoa/warsachive`의 `web/content/archive.json`을 읽고 새 기록 한 건을 누적하도록 구성했다.
- 기존 기록과 같은 ID가 있으면 중복 커밋하지 않도록 구성했다.
- GitHub 커밋이 실패하면 같은 기록을 다음 발행 주기에 다시 시도한다.
- 원시 자료와 라벨링 중간 결과는 NAS에만 남고 정보화된 공개 기록만 GitHub로 이동한다.

## Back 관리자 관제 화면

처리 관제 화면의 책임 위치를 `front/admin`이 아닌 `back/admin`으로 바로잡았다.

- React/Vite 기반 NAS 관제 화면을 `back/admin`에 생성했다.
- 관리자 포트를 `9231`로 고정했다.
- Docker Compose에서 `${ADMIN_PORT:-9231}:9231`로 연결했다.
- 컨테이너 시작 시 수집기, 발행기와 관리자 서버를 함께 실행한다.
- 관리자 서버가 다음 NAS 상태 파일을 직접 읽는다.
  - `/data/state/collection.json`
  - `/data/state/publication.json`
  - `/data/raw/documents.json`
  - `/data/labeled/documents.json`
  - `/data/informationized/records.json`
- `/api/status`에서 토큰이나 원문 내용 없이 처리 수량과 스케줄 상태만 제공한다.
- 화면은 15초마다 상태를 갱신한다.
- 수집 주제 수, 문서 수, 정보화 기록 수와 발행 수를 표시한다.
- 마지막·다음 수집 시각과 마지막·다음 발행 시각을 표시한다.
- 최근 정보화 기록과 공개 여부를 표시한다.

접속 주소:

```text
로컬: http://127.0.0.1:9231
NAS 내부망: http://NAS-IP:9231
상태 API: http://NAS-IP:9231/api/status
```

포트 `9231`은 공유기에서 인터넷으로 전달하지 않고 NAS 내부망에서만 허용하는 것을 원칙으로 한다.

## 즉시 필요한 보안 조치

NAS 발행용 GitHub Personal Access Token은 `kenitoa/warsachive` 저장소에 공개 기록을 누적 커밋하기 위한 필수 운영 설정이다. 이 토큰 흐름은 제거하지 않는다.

다만 `back/.env`의 실제 토큰 값이 점검 출력, 문서, 채팅, 화면 캡처, Git 커밋 중 하나에 노출된 경우 해당 값은 더 이상 안전하다고 볼 수 없다. 이때 조치 대상은 발행 기능이 아니라 노출된 실제 토큰 값이다.

반드시 수행할 작업:

1. 실제 토큰 값이 노출된 적이 있으면 GitHub에서 해당 토큰 값을 폐기한다.
2. `kenitoa/warsachive` 저장소 하나만 선택한 새 Fine-grained token을 만든다.
3. Repository permission은 `Contents: Read and write`만 부여한다.
4. 새 토큰을 NAS의 `back/.env`에 입력한다.
5. 토큰 값을 Markdown, Git 커밋, 화면 캡처와 채팅에 기록하지 않는다.
6. `back/.env`가 `.gitignore`에 의해 제외되는지 커밋 전에 확인한다.
7. `npm run verify:secrets`로 저장소 안에 실제 토큰 값이 남지 않았는지 확인한다.

이 문서에는 실제 토큰 값을 기록하지 않았다.

## 위험 요소 해소 상태

- Docker/WSL 미검증 위험은 `docker compose config`, 컨테이너 실행, `/api/health` healthcheck를 수행하는 `nas-install.sh`로 운영 시 차단하도록 조치했다.
- 외부 출처 등록 위험은 `audit:sources`와 `verify:ops`에서 정책 확인, robots.txt, 호출 간격을 통과해야만 운영 수집에 들어가도록 조치했다.
- 토큰 노출 위험은 `.env` ignore, `.env` 권한 제한, `verify:secrets` 토큰 스캔으로 조치했다. 단, 이 검증은 NAS 발행 토큰 자체를 제거하는 것이 아니라 저장소 안에 실제 값이 남지 않게 막는 장치다.
- `back/admin` 인터넷 노출 위험은 Docker/NAS 내부망 관제 화면으로만 유지하고, `front` Pages 배포에서는 admin을 제거해 조치했다.
- GitHub Actions Node 경고 위험은 Pages 워크플로에서 Node 22.13을 명시해 조치했다.

## 추가 점검 및 수정

- 로컬 실행 시 GitHub 토큰이 없으면 공개 JSON이 갱신되지 않아 front가 예시 기록만 표시하던 문제를 확인했다.
- `WAR_ARCHIVE_FRONT_ARCHIVE_PATH` 로컬 발행 경로를 추가해 `npm run local:sync`가 `front/web/content/archive.json`을 직접 누적 갱신하도록 수정했다.
- 기본 `topics.json`에서 구축용 인라인 예시 주제를 제거하고 `임진왜란` 로컬 파일 출처 2개를 등록했다.
- 공개 `archive.json`에서 샘플 기록을 제거하고 실제 생성된 `imjin-war` 기록만 남겼다.
- 검증 결과: 백엔드 테스트 `14/14` 통과, 출처 감사 `2/2` 로컬 파일 통과, front 빌드에서 `/archive/imjin-war` 정적 페이지 생성 확인.
- 사용자가 정의한 흐름에 맞춰 정보화 산출물에 `history-curator-v1` 큐레이터 양식을 추가했다.
- 수집 사이클을 `등록된 전체 출처 sweep`으로 수정하고, 라벨링에 신뢰도·연관성·맥락 그룹을 추가했다.
- `PROCESSING_DELAY_MS=600000` 기본값을 추가해 수집과 발행 사이 10분을 가공 시간으로 보장했다.
- Docker Compose에 고정 컨테이너 이름과 `/api/health` healthcheck를 추가해 NAS에서 상태 확인을 쉽게 했다.
- `PUBLICATION_MIN_QUALITY_SCORE=0.6` 품질 게이트를 추가해 40분 발행 주기에서 기준 미달 기록은 front에 올리지 않도록 했다.
- `kenitoa/warsachive`에 올라가는 `front` 저장소에서 `admin` workspace와 Pages `/admin/` 배포 단계를 제거했다. 관제 화면은 `back/admin` 내부망 Docker 화면으로만 유지한다.
- `verify:secrets`, `preflight`, `preflight:strict`, `verify:ops` 운영 검증 명령을 추가해 토큰 유출, admin 재등록, 품질 게이트 누락, Docker 설정 누락을 자동 점검하도록 했다.
- `nas-install.sh`가 `.env` 권한을 제한하고, 컨테이너 실행 후 Docker healthcheck 상태까지 확인하도록 강화했다.
